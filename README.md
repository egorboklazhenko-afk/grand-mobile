# Grand Copilot · Decentrathon 6.0

Рабочее место поддержки Grand Mobile: Windows-приложение, автономный HTTP-сервис и пакетная обработка JSONL. Это проверенный инженерный MVP. По сообщению пользователя, программа с Groq работает. Конкурсная точность классификации и качество Groq-черновиков независимо не оценивались.

## Запуск программы

В готовой Windows-сборке откройте **Grand Copilot.exe** двойным щелчком. Python и браузер не нужны. Требуется Microsoft Edge WebView2 Runtime; на компьютере, где выполнялась сборка, он установлен и приложение проверяется с ним.

Если правила ещё не загружены, выберите **Настройки → Загрузить архив кейса** и укажите `grand-support-copilot-handout-2026-10-27.tgz`. Программа извлечёт только `rules.json`, а не обращения игроков. Можно выбрать отдельный `rules.json`.

В **Настройки → Groq API** введите ключ Groq и нажмите **Подключить Groq**. Ключ действует до закрытия программы, на диск не записывается. Это ключ из GroqCloud, не из Grok/xAI. Наличие ключа в настройках ещё не означает успешный запрос: смотрите статус обработки и JSON-аудит.

Новые обращения и правки сохраняются в `user-data/` рядом с программой; правила — в `data/`. Эти каталоги приватные. Если переносите программу на другой компьютер, сначала перенесите сам `.exe`, затем импортируйте разрешённые правила. Не включайте пользовательские данные в публичную сдачу.

## Что работает

- Категории и приоритеты по контракту, извлечение ника, заявленных ссылок и наличия вложений.
- Отдельное хранение утверждений заявителя и обвиняемого; эти утверждения не становятся проверенными фактами.
- BM25-поиск по 266 пунктам и одному ненумерованному разделу. Ссылки содержат контекст раздела и исходный текст.
- Черновики на ru/kk/uz/en/es/pt; нормализация казахских замен cp1251. Нужна проверка переводов носителями.
- Обязательная эскалация платежей, аккаунтов, апелляций, жалоб на администратора.
- Дубликаты, совпадающие после нормализации регистра, пробелов и пунктуации, одного заявителя в пределах часа при наличии идентификатора и времени. Разные цели жалобы/серверы не объединяются. Это не семантический поиск дублей.
- Очередь, редактирование, локальная обратная связь и эскалация в интерфейсе. Кнопка принятия сохраняет черновик; реальной отправки игроку нет.
- Groq для семантической классификации и RAG-черновика в одном запросе. Не прошедший проверки черновик заменяется шаблоном. Без API работает отдельный эвристический режим.

## Исходный код: запуск API

Python 3.12+, без внешних Python-зависимостей для API/CLI.

```powershell
python setup_data.py --archive "C:/path/grand-support-copilot-handout-2026-10-27.tgz" --with-tickets
python -m copilot.server
```

Сервис слушает `http://127.0.0.1:8765`. Эндпоинты: `POST /triage`, `GET /health`, `POST /feedback`. По умолчанию только loopback. Для внешнего размещения нужны шлюз с аутентификацией, TLS, ограничения запросов и политика хранения.

Пример запроса:

```json
{"kind":"complaint","messages":[{"role":"player","text":"Demo_Player оскорбил меня в чате, 2.1.","attachments":2}]}
```

Ответ содержит поля контракта `lang`, `category`, `priority`, `is_spam_or_duplicate`, `extracted`, `draft_reply`, `needs_human`, `confidence`, `reasons`, а также расширение `audit`. `has_evidence` означает наличие метаданных вложения, а не проверенное доказательство. `confidence` — некалиброванная эвристика, не вероятность.

Скрытый ввод ключа для API:

```powershell
.\start-groq.ps1
```

Или задайте `COPILOT_PROVIDER=groq`, `GROQ_API_KEY` и `GROQ_MODEL=openai/gpt-oss-120b` в окружении запуска. Не добавляйте ключ в код, JSONL, команду с буквальным ключом или Git. В поставке ключей нет.

## Пакетное предсказание

```bash
make predict IN=tickets.jsonl OUT=pred.jsonl
```

На Windows без Make:

```powershell
python -m copilot.cli --input tickets.jsonl --output pred.jsonl
```

Поддерживаются `.jsonl` и `.jsonl.gz`. Дедупликация использует порядок событий: подавайте хронологический поток. В CLI состояние живёт в пределах запуска. Без заявителя/времени совпадения не выдаются за подтверждённые дубли.

Docker (сборка не запускалась в этой среде):

```bash
docker build -t grand-copilot .
docker run --rm -p 127.0.0.1:8765:8765 -v "$PWD/data:/app/data:ro" grand-copilot
docker run --rm -v "$PWD/data:/app/data:ro" -v "$PWD/runtime:/app/runtime" grand-copilot -m copilot.cli --input data/tickets_valid.jsonl --output runtime/pred.jsonl
```

## Проверки и метрики

```powershell
python -m unittest discover -s tests -v
python -m copilot.evaluate --input data/tickets_valid.jsonl --output reports/validation.json
```

Для платного API сначала используйте `--limit 10` и отдельный файл отчёта. Оценка не делает повторный платный запрос для проверки утечки: сравнивает точную проекцию входа. В локальном режиме также проверяет неизменность результатов после подстановки ответов администратора и исходов.

`reports/validation.json` — реально выполненный прогон 1000 выданных обращений в режиме **retrieval_templates**, без Groq. Нулевое число несуществующих идентификаторов не означает нулевого числа смысловых ошибок. Доля эскалации — не точность. В исходной валидации нет категории и приоритета, поэтому accuracy/macro-F1 оставлены `null`, а не вычислены по собственным предсказаниям.

Языковые метки исходных данных эвристические. Для оценки языка нужен независимый просмотр. Качество ответов должна подтвердить слепая оценка администраторов и носителей kk/uz. Их оценки пока отсутствуют.

## Модель и стоимость

По умолчанию Groq: `openai/gpt-oss-120b`, strict JSON Schema, low reasoning, без веб-поиска. [Поддерживаемые модели и цены](https://console.groq.com/docs/models), [структурированный вывод](https://console.groq.com/docs/structured-outputs), [параметры reasoning](https://console.groq.com/docs/reasoning).

В конфигурации зафиксированы опубликованные ставки: $0.15 за 1 млн входных и $0.60 за 1 млн выходных токенов. Стоимость ответа рассчитывается из `usage`; перед сдачей перепроверьте тариф. Пример, не измерение: 2000 входных + 1200 выходных токенов = $0.00102. Это ниже целевого $0.002, но реальные токены и задержку ещё нужно измерить; функциональную работоспособность с Groq пользователь подтвердил. Ошибки/таймауты могут оставлять неизвестную стоимость, она не подменяется нулём.

Опционально: `OLLAMA_MODEL` включает локальный Ollama на `127.0.0.1:11434`. Модель и её веса не поставляются. [Документация API](https://docs.ollama.com/api/chat).

Таймаут сетевого вызова 3.5 с; это не гарантия p95 всего сервиса. Базовые локальные задержки в отчёте относятся к движку, а не к холодному запуску `.exe`, сети или нагрузке.

## Защита от утечки и ошибки исходников

`input_view` допускает только входные поля обращения и сообщения `player` / `reported_player`. Сообщения `admin`, `verdict`, `punishment`, `violation`, входные `category` и `priority` не попадают в инференс. Ответы администраторов нельзя использовать как признаки валидационного тикета.

Общий DM не получает выдуманного номера: для подготовки к рассмотрению цитируется существующий пункт 1.1.1 раздела «Правила жалоб» о необходимости объективных доказательств. При зелёной зоне и территории дома выбираются соответствующие существующие пункты. Все выдаваемые ссылки проверяются как нумерованные points[].ref с сохранением раздела в аудите.

Шаблоны и валидатор не доказывают смысловую корректность LLM-ответа. После генерации требуется администратор. Отсутствует реальная база инструкций по механикам игры: вместо выдуманных шагов сервис уточняет вопрос и эскалирует.

## Сборка Windows

```powershell
.\build-desktop.ps1
```

Используются pywebview и PyInstaller, версии зафиксированы в `requirements-desktop.txt`. Это нативное Windows-окно на системном WebView2 с Python-движком и прямым мостом; отдельный браузер и HTTP-сервер для приложения не запускаются. ## Данные и публикация

Конкурсные данные не входят в архив исходников. Не публикуйте `data/`, `user-data/`, `runtime/`, примеры из выгрузки или производные выборки. Удаление после конкурса выполняется по срокам организаторов: в течение 14 дней после объявления победителей без отдельного соглашения. Лицензию собственного кода выбирает команда; см. `NOTICE.md`.


## Приёмочная проверка поставки

Команда `python verify_submission.py` выполняет тесты, 32 авторских синтетических сценария на шести языках, проверяет HTTP-контракт и ошибочные запросы, пакетный вывод, дубликаты, параллельные локальные запросы и существование нумерованных цитат на 1000 обращений. Нужны локальные файлы `data/rules.json` и `data/tickets_valid.jsonl`. Внешние API в этом сценарии отключаются, пользовательские ключи не считываются. Результат: `reports/acceptance.json`. Синтетическая проверка не заменяет независимую оценку на скрытом тесте.

Для Groq добавлен предварительный контроль размера запроса: при превышении настроенного допуска стоимости запрос не отправляется, используется локальный режим. Допуск считается консервативно по размеру UTF-8, резерву протокола и максимальному числу выходных токенов при зафиксированных ставках. Это не замер счёта провайдера. Интерфейс явно сообщает о fallback, поэтому локальный ответ не выдаётся за успешную генерацию AI.
